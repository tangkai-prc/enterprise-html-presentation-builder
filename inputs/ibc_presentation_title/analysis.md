# IBC_template.pptx 模板分析

## 结论

分析企业 PPT 模板。

## 当前目标

对 `input/templates/IBC_template.pptx` 做第一阶段模板分析，抽取可复用的风格 token、页面类型、素材来源规则、素材放置规则、单文件 HTML 约束和信息缺口。当前阶段不生成最终 HTML。

## 输入材料

- 模板文件：`input/templates/IBC_template.pptx`
- 用户标注：
  - 第 0 页：封面
  - 第 1 页：中文目录样式
  - 第 2 页：英文目录样式
  - 第 13 页：尾页
- 解析结果：
  - PPTX 内部共有 14 张幻灯片，对应 `slide1.xml` 到 `slide14.xml`
  - 用户页码为 0-based；PPTX 内部 slide 编号为 1-based
  - 幻灯片比例为 16:9，PPT 尺寸为 `12192000 x 6858000` EMU
  - 建议 HTML 逻辑画布：`1280 x 720`
  - 包含 2 个母版、38 个版式、6 个常规图片素材和 1 个 WDP 图片

## 推测内容

- `#016F67` 应作为主品牌绿色使用，需要品牌手册确认。
- `#00706B` 应作为目录页或强调元素的辅助绿色，需要确认是否为正式辅助色。
- 右上角标识组合图可作为 MVP 临时 logo，但正式交付应替换为官方 SVG 或高清 PNG。
- 封面、目录和尾页的波纹背景可先用提取图片还原；若追求更轻量的单文件 HTML，可后续用 CSS/SVG 近似重建。
- 第 3 到第 12 页主要是章节标题 + 多级小节导航 + 图文内容页版式，不是用户已标注的重点页，但可作为后续内容页模板来源。

## 信息缺口

- 缺少官方品牌手册，无法确认颜色、字体、logo 安全区和最小尺寸。
- 缺少独立官方 logo 源文件，当前只有 PPT 内嵌组合 PNG。
- 缺少最终演示标题、项目名称、汇报对象、语言策略和日期规则。
- 缺少目录真实章节文本。
- 缺少普通内容页真实内容、图片、图表、截图和数据来源。
- 缺少素材授权状态，PPT 内嵌图片可视为用户提供，但是否可对外复用仍需确认。
- 缺少交付模式确认：严格单文件 HTML，还是 HTML + assets 文件夹。

## 素材来源规则

- logo 优先级：
  1. 用户提供的官方 SVG logo。
  2. 用户提供的官方高清 PNG。
  3. PPT 内嵌 `image1.png` 作为 MVP 临时素材。
- 背景优先级：
  1. PPT 内嵌背景图。
  2. 导出的整页背景图。
  3. 用 CSS/SVG 重建波纹和色块。
- 普通内容页图片：
  - 必须由用户提供或来自批准材料。
  - 缺失时使用明确占位符，不使用随机网络图片。
- 图表和数据：
  - 不得编造正式数据。
  - 示例数据必须标注为演示用 dummy data。
- 单文件 HTML：
  - MVP 可将小型 PNG/JPEG 转为 base64 内嵌。
  - 若背景图片体积过大，应建议改为 HTML + assets 文件夹，而不是强行内嵌。

## 素材放置规则

- Logo：
  - 普通页默认右上角。
  - 封面 logo 遵循模板右上角位置。
  - 不拉伸、不裁剪、不改色。
- 标题：
  - 内容页标题位于顶部左侧，避免与右上 logo 冲突。
  - 封面标题可位于中部深绿色波纹带上。
- 目录：
  - 左侧保留竖向 `CONTENTS` 标识。
  - 中文版保留 `目录` 标识。
  - 章节编号和章节文本按四行纵向排列。
- 页码：
  - 内容页和目录页统一右下角。
  - 封面和尾页可不显示页码，除非模板要求。
- 背景和装饰：
  - 封面、目录、尾页优先复用 PPT 内嵌背景图。
  - PPTX 图片若没有 `srcRect` 裁剪参数，应按 XML 几何框精确拉伸到 `100% 100%`，不要用 `background-size: cover` 裁切；本模板的 `image3.png` 和 `image4.png` 都属于这种情况。
  - 普通内容页的浅色波纹可作为低透明背景，不应影响正文可读性。
  - 尾页能源图形左右贴边放置，保持白色图形与绿色背景的对比。

## 推荐转换策略

Hybrid approach。

- 用 PPT 风格的“版式系统”写 HTML：优先读取母版、版式、占位符、坐标、字体、颜色和图片关系，而不是按截图手工临摹。
- 把 `slideMaster` 视为全局品牌层，把 `slideLayout` 视为页面版式层，把 `slide` 视为具体内容层。
- HTML 中建立对应的 layout class，例如 `cover`、`agenda-zh-layout2`、`agenda-en-layout3`、`content-nav`、`closing`。
- 对 PowerPoint 加粗效果，HTML 可优先用 `font-weight: 800/900` 加轻微 `text-shadow` 做视觉增重；中文竖排文字不优先使用负字距，避免破坏坐标对齐。
- 封面、目录、尾页先使用 PPT 内嵌背景图片还原视觉；背景图应按 PPTX 的图片框非等比拉伸规则还原，避免 `cover` 裁切造成渐变和波纹位置生硬。
- 内容页优先用 HTML/CSS 重建版式、标题、小节导航、图片区和正文区。
- Logo 初版可使用 PPT 内嵌组合 PNG，正式版要求用户提供官方 SVG 或高清 PNG。
- 不承诺 PPTX 到 HTML 的逐对象精确转换。

## 单文件 HTML 约束

- 使用 `1280 x 720` 的 16:9 固定逻辑画布，浏览器中按视口等比缩放。
- CSS、JS、必要 SVG 和小图可内嵌。
- 不依赖 CDN、远程字体、远程图片或外部 API。
- 支持键盘翻页、全屏和当前页状态显示。
- 图片过大时需要在“严格单文件”和“可维护体积”之间做取舍。
